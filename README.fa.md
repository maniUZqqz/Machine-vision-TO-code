# Machine-vision-TO-code (mv2code نسخهٔ ۲)

فارسی | [English](README.md)

یک **اسکرین‌شاتِ رابط کاربری را به HTML/CSSِ واقعی و قابل‌ویرایش** تبدیل می‌کند؛ با بینایی ماشینِ کلاسیک، بدون API هوش مصنوعی و بدون GPU.
صفحه‌های فارسی (راست‌به‌چپ) و انگلیسی، روشن و تیره، دسکتاپ و موبایل.

* **متنِ واقعی**: Tesseract با `fas+eng` (پیش‌فرض) یا EasyOCR (اختیاری)، یکدست‌سازیِ حروف و ارقامِ فارسی و نیم‌فاصله، ترتیبِ درستِ کلمات در راست‌به‌چپ.
* **چیدمانِ واقعی**: برش بازگشتیِ XY ← `flex` تودرتو، `<table>` و بخش‌های تمام‌عرض؛ نه تکه‌تصویرهای با موقعیتِ مطلق.
* **اجزای واقعی**: دکمه، ورودی/انتخاب/ناحیهٔ متن، نشان (badge)، چک‌باکس/رادیو/سوییچ، کارت (حاشیه، گوشهٔ گرد، سایه، گرادیان)، خط جداکننده، آیکن (تبدیل به SVGِ درون‌خطی)؛ عکس‌ها تصویر می‌مانند.
* دو حالتِ خروجی: `responsive` (برچسب‌های معنایی، flex/table، متغیرهای CSS، بازچینش در ۳۶۰/۷۶۸/۱۲۸۰ پیکسل) و `exact` (دقیقاً مثل تصویر، با موقعیتِ مطلق).
* **درختِ اجزا به‌صورت JSON** (`tree_json`، ← [docs/tree-json.md](docs/tree-json.md)) برای ابزارهایی که بخش/بلوک/متن/رنگ می‌خواهند.
* یک **بنچمارکِ صادقانه** (`python -m bench run`) که اعدادِ همین فایل از آن آمده‌اند: قبل (کدِ نسخهٔ ۱) و بعد.

## نصب

```bash
pip install -e .                       # هسته: numpy + opencv + Pillow (سبک)
pip install -e ".[ocr-tesseract]"      # + pytesseract ؛ و روی لینوکس: sudo apt install tesseract-ocr tesseract-ocr-fas tesseract-ocr-eng
pip install -e ".[browser]" && python -m playwright install chromium    # حلقهٔ بازخورد، --score و بنچمارک
pip install -e ".[web]"                # برنامهٔ وب (Django)
pip install -e ".[ocr-easyocr]"        # اختیاری و سنگین (torch)؛ روی متنِ فارسیِ ریز حدود دو برابر دقیق‌تر
```

نسخه‌های سنجیده‌شده: `requirements.txt`. فونت‌ها (وزیرمتن و Inter با مجوز SIL OFL 1.1) داخلِ بسته هستند (`mv2code/fonts`).

## استفاده

```bash
mv2code shot.png -o out/ --mode responsive          # out/index.html + fonts/ + tree.json + report.json
mv2code shot.png -o out/ --mode both --score --zip  # حالت exact هم، امتیازهای صادقانه (نیاز به playwright)، result.zip
```

```python
from mv2code import convert
r = convert("shot.png", mode="responsive", lang="auto")   # lang: auto | fa | en ؛ ocr: auto | tesseract | easyocr | none
r["html"], r["css"], r["tree_json"], r["report"]
from mv2code.bundle import write_bundle; write_bundle(r, "out/")
```

برنامهٔ وب (بارگذاریِ تصویر ← اسکرین‌شات و صفحهٔ ساخته‌شده کنارِ هم با امتیازها ← دانلودِ ZIP):
`python manage.py migrate && python manage.py runserver` ؛ REST: ‏`POST /api/convert/` (فیلدهای `image` و `mode` و `languages`).

خطاها روشن‌اند (`ImageError` برای تصویرِ خراب/خیلی کوچک/خیلی بزرگ، `ValueError` برای گزینهٔ نادرست، کدِ خروجیِ ۲ و ۳ در CLI).
تصویرهای بزرگ کوچک می‌شوند (`max_width=2400`)، برای اسکرین‌شاتِ رتینا `--dpr 2` و خروجی قطعی (deterministic) است.

## چطور کار می‌کند

`segment.py` (تحلیلِ ناحیه‌های هموار: رنگِ تخت، گرادیان، حاشیه، گوشهٔ گرد، سایه، عکس، خط) ← `textdet.py` (جعبهٔ دقیقِ هر خطِ متن)
← `ocr.py` و `persian.py` (خواندنِ برش‌ها و پاک‌سازیِ فارسی) ← `textstyle.py` (فونت/وزن/اندازه/رنگ با «ساختن و مقایسه» با فونت‌های همراه)
← `build.py` (نقش‌ها) ← `layout.py` (XY-cut و جدول) ← `emit.py` (HTML/CSS) ← `refine.py` (رندر، مقایسهٔ هر المان، اصلاح، نگه‌داشتنِ بهترین).

## بنچمارکِ صادقانه

نسخهٔ ۱ «۹۱٫۴٪ و ۹۵٫۵٪ شباهتِ پیکسلی» گزارش می‌کرد. آن عدد هر پیکسلِ نزدیک (کمتر از ۳۰ سطحِ خاکستری) را برابر می‌گیرد؛
**یک صفحهٔ کاملاً خالی به رنگِ پس‌زمینه هم حدودِ ۸۸٪ می‌گیرد**، و صفحه‌ای که از تکه‌تصویرِ خودِ عکس ساخته شده بالا امتیاز می‌گیرد ولی به‌عنوانِ کد بی‌ارزش است.
بنچمارکِ جدید (`bench/`) ۸۰ صفحه را از قالب‌های خودش می‌سازد (۱۰ نوع صفحه × فارسی/انگلیسی × روشن/تیره × ۲ نمونه، با وزیرمتن/Inter و رقمِ فارسی) به‌علاوهٔ دو نمونهٔ واقعی،
حقیقتِ زمینه (نقش، جعبه، متن، استایلِ هر المان) دقیق است و این‌ها را می‌سنجد:

* **متن**: سهمِ متنِ درست که در خروجی «متنِ انتخاب‌پذیرِ واقعی» است، نرخ خطای نویسه (CER) فارسی و انگلیسی جدا، ترتیبِ کلمات، رقمِ فارسی/لاتین؛
* **ساختار**: دقت/بازیابی/F1 با IoU≥۰٫۵ برای هر نقش (دکمه، ورودی، تصویر، بلوکِ متن، کارت، جدول، ناوبری؛ و آیکن، نشان، کنترل)؛
* **بصری**: SSIM و شباهتِ پیکسلیِ سخت‌گیرانهٔ خروجیِ رندرشده با اسکرین‌شات؛
* **قابلیتِ ویرایش**: سهمِ مساحتِ صفحه که HTML/CSSِ واقعی است (عکس می‌تواند تصویر بماند، بقیه نه)؛
* **واکنش‌گرایی**: بدونِ سرریزِ افقی و بدونِ روی‌هم‌افتادنِ متن در ۳۶۰ و ۷۶۸ و ۱۲۸۰ پیکسل؛
* **سرعت و RAM** روی همین سرورِ ۲ هسته‌ای.

`python -m bench run --quick` (۲۴ صفحه) یا `--full` (۸۰ صفحه) جدول را چاپ و `bench/results.json` را می‌نویسد (برای نگه‌داشتنِ فایلِ ثبت‌شده `--out` بده؛ `--mode exact` برای خروجیِ دقیق؛ `--refine on` برای سنجشِ حلقهٔ بازخورد؛ پیش‌فرض `--refine off` است، همان تنظیمِ همهٔ جدول‌های زیر). به tesseract، playwright و یک Chromiumِ بدون‌سر نیاز دارد.
`python -m bench compare before.json after.json --md` جدولِ قبل/بعدِ زیر را می‌سازد.

### مقایسهٔ موتورهای OCR (همان برش‌ها، روی همین سرورِ ۲ هسته‌ای)

خطوطِ متن را خودِ تحلیلِ پیکسلی پیدا می‌کند، پس همهٔ موتورها *همان برش‌ها* را می‌خوانند. نرخ خطای نویسه نسبت به حقیقتِ دقیق:

| موتور | CER | سرعت / سنگینی | نتیجه |
|---|---|---|---|
| **Tesseract 4.1 با `fas+eng`** (مدل‌های fast، از apt) - پیش‌فرض | ۰٫۹٪ فارسی و ≈ ۰٪ انگلیسی روی شش صفحهٔ متنوع؛ **۱۴٫۱٪ روی سه صفحهٔ فارسی پر از متنِ ۱۱ تا ۱۴ پیکسلی** | حدود ۳٫۵ ثانیه در هر صفحه، بدون torch، حدود ۲۰۰ مگ RAM | **پیش‌فرض** (بهترین دقت به‌ازای منبع) |
| Tesseract با `tessdata_best` | ۱۶٫۴٪ (همان سه صفحه) | همان | بدونِ بهبود |
| Tesseract + پیش‌پردازشِ بیشتر (ارتفاع ۳۴ تا ۶۴، Lanczos، Otsu، تیزکردن، تلاشِ دوباره با رقم‌های مجاز) | ۱۴٫۵ تا ۱۶٪ | ۱ تا ۳ ثانیه بیشتر | بدونِ بهبود؛ فقط تلاشِ دوباره برای خط‌های ضعیف مانده |
| بهترینِ ۶ حالت (اوراکل) / انتخاب با بازسازیِ متن با وزیرمتن | ۹٫۹٪ / ۱۴٫۱٪ | | انتخاب با بازسازی خوانشِ بهتر را پیدا نکرد |
| **EasyOCR با `fa+en`** (CPU، اضافهٔ اختیاری) | **۶٫۲٪** (دو صفحه از همان سه) | بیش از ۱۰۰ ثانیه در هر صفحه، torch حدود ۱٫۵ گیگ | روی متنِ فارسیِ ریز حدود دو برابر دقیق‌تر ولی برای این سرور سنگین ← بک‌اندِ اختیاری (`ocr="easyocr"`) |
| RapidOCR / PaddleOCR (ONNX) | ارزیابی نشد | | مدلِ تشخیصِ فارسی از منابعِ در دسترس پیدا نشد؛ رابطِ بک‌اند (`mv2code/ocr.py`) اضافه‌کردنش را ساده می‌کند |


### مشکلاتِ نسخهٔ ۱ (با خواندن و اجرای آن پیدا شد)

* «شباهتِ پیکسلی»‌اش هر پیکسلِ نزدیک (کمتر از ۳۰ سطحِ خاکستری) را برابر می‌گیرد: **صفحهٔ کاملاً خالی ۸۸ تا ۹۴٪ می‌گیرد**؛ پس ۹۱٫۴٪ و ۹۵٫۵٪ چیزی دربارهٔ کیفیتِ کد نمی‌گفت.
* کانتینرهای پیچیده به‌صورتِ **برشی از خودِ تصویر** گذاشته می‌شد (`bg_image_data_uri`) و همه‌چیز `position:absolute` بود (و برای صفحهٔ باریک یک ترفندِ `transform: scale()`): امتیازِ پیکسلیِ بالا ولی کدِ بی‌ارزش (نه قابل‌ویرایش، نه واکنش‌گرا).
* `text_detector.py` **اصلاح‌های دستی فقط برای دو تصویرِ نمونه** دارد (`'سوشمند' ← 'هوشمند'`، `'FLDW' ← 'FLOW'`، `'DOSIN' ← 'DOSING'` ...): نتیجهٔ نمونه‌ها را بالا می‌برد و برای هیچ تصویرِ دیگری کاری نمی‌کند.
* EasyOCR (torch، حدود ۱٫۵ گیگ) در هر درخواست: روی همین سرور ۱۱۸ ثانیه و ۱٫۸ گیگ RAM برای هر صفحه؛ رقم و حروفِ فارسی، ترتیبِ خط و متنِ دوسویه رسیدگی نمی‌شد؛ فقط بلوک می‌یافت، نه جدول/ناوبری/ورودی/نشان (F1 ساختار ۱۵٫۵٪).
* روی تصویرهای عکس‌گونه (`1122.png`، یک تصویرِ SCADA ساخته‌شده با هوش مصنوعی) نسخهٔ ۱ SSIM بالاتری می‌گیرد فقط چون تکه‌عکس می‌چسباند (۱۲٫۸٪ قابل‌ویرایش)؛ نسخهٔ ۲ عکس را تصویر نگه می‌دارد و باقی را کد می‌کند و صادقانه آنجا کمتر می‌گیرد (SSIM ۵۲٪).


## محدودیت‌های شناخته‌شده (صادقانه)

* **بنچمارکِ مصنوعی.** ۸۰ صفحه از قالب‌های خودمان ساخته شده؛ اعداد پیشرفت و پسرفت را نشان می‌دهند، نه تعمیم‌پذیری را. روی دو نمونهٔ واقعی فقط بررسیِ بصری/قابلیتِ ویرایش/متنِ رونویسی‌شده هست (`1524.png` یک داشبوردِ واقعیِ فارسیِ Bootstrap است: SSIM ‏۹۲٫۹٪ و ۲۸ از ۳۲ خطِ رونویسی پیدا شد).
* **OCR حلقهٔ ضعیف است برای متنِ فارسیِ ریز** (۱۱ تا ۱۴ پیکسل): حدود ۱۴٪ خطای نویسه با Tesseract؛ پس متنِ تولیدشده واقعی است ولی گاهی غلط. EasyOCR آن را نصف می‌کند ولی torch می‌خواهد.
* **انحرافِ چیدمان**: جای عناصر از فاصله‌های اندازه‌گیری‌شده بازسازی می‌شود؛ بعضی صفحه‌ها ۱۰ تا ۳۰ پیکسل در راستای عمودی منحرف می‌شوند (ستونِ «در جای خودش» در جدول) و ۲۰ تا ۳۰٪ رندرهای عرضِ کم هنوز سرریز یا روی‌هم‌افتادگی دارند. حلقهٔ بازخورد متن را جابه‌جا می‌کند ولی انحرافِ ساختاری را درمان نمی‌کند.
* ردیف‌ها فقط **زیرِ حدودِ ۹۳٪ عرضِ اصلی** می‌شکنند؛ جدول برای شناسایی به خطِ ردیف یا نوارِ سرستون نیاز دارد؛ کارت‌های تکراری ردیفِ flex می‌شوند (هنوز CSS grid نیست)؛ عناصرِ روی‌هم‌افتاده به «stack»های مطلقِ کوچک برمی‌گردند.
* کنترل‌ها: چک‌باکس/رادیو/سوییچ با بازیابیِ حدودِ ۲۵٪ پیدا می‌شوند؛ آیکن‌ها حدودِ ۵۰٪ (تک‌رنگ‌ها SVG درون‌خطی، چندرنگ‌ها برشِ تصویر).
* فقط وزیرمتن و Inter تولید می‌شوند؛ فونت‌های دیگر (سریف، نمایشی) جایگزین می‌شوند. فاصلهٔ حروف، شفافیت، محو‌شدگی، سایهٔ متن، گرادیانِ چندنقطه‌ای و الگوی پس‌زمینه مدل نمی‌شوند؛ سایه‌ها تقریباً سیاه فرض می‌شوند.
* «اسکرین‌شات»های عکس‌گونه یا ساخته‌شده با هوش مصنوعی به ساختار تبدیل نمی‌شوند: ناحیهٔ عکس تصویر می‌ماند و باقی تلاشِ بهینه است.
* اسکرین‌شاتِ JPEG با آستانهٔ تطبیقیِ نویز پشتیبانی می‌شود ولی **هنوز در بنچمارک نیست**؛ حاشیه‌های ۱ پیکسلیِ محو فقط تا حدی بازیابی می‌شوند.
* سرعت: ۴ تا ۹ ثانیه برای هر صفحه روی ۲ هسته (Tesseract بیشترش را می‌برد)، حدود ۲۲۰ مگ RAM؛ حلقهٔ بازخورد چند ثانیه اضافه می‌کند.


## تست و CI

```bash
pip install -e ".[dev,web,ocr-tesseract]"     # pytest + Django + pytesseract (+ [browser] و یک Chromium برای تست‌های golden/مرورگر)
python -m pytest -q
```

شامل: تستِ واحد برای هر مرحله، تستِ سرتاسریِ CLI و API، و صفحه‌های طلایی (نیاز به tesseract و مرورگرِ بدون‌سر؛ وگرنه رد می‌شوند).
`.github/workflows/ci.yml` تست‌های سریع را در هر push و بنچمارکِ مرورگر را زمان‌بندی‌شده/دستی اجرا می‌کند.
